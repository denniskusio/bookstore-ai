# CLAUDE.md

Guidance for AI coding assistants working in this repository. The same conventions apply to human contributors.

## Project

Bookstore AI is an online bookstore built as Spring Boot microservices (`api-gateway`, `user-service`,
`book-service`, `order-service`, `assistant-service`) with AI features running on a local LLM: semantic search and a
RAG-based book advisor. It uses PostgreSQL with pgvector, Kafka (KRaft), Ollama and Spring AI, and deploys with Docker
Compose and Kubernetes (kind). See `README.md` for the architecture, `ROADMAP.md` for planned work and `docs/adr` for
the reasoning behind the main decisions.

## Reviewing code

When reviewing, cite `file:line`, explain the risk and suggest a fix. Look at the non-functional aspects first, because
they separate production code from demo code:

- **Error handling** - what happens on every failure path? Is anything swallowed, leaked or retried forever?
- **Idempotence** - what if a message or request is delivered twice, or two copies run concurrently?
- **Testability** - can the logic be tested without the whole stack? Are the failure paths tested, not just the happy path?
- **Observability** - can an operator tell what happened (logs with correlation ID, metrics, health)?
- **Security** - input validation, authorisation, data exposure, prompt injection for anything LLM-related.

Then check correctness, naming and consistency with the conventions below.

## Conventions - the book-service slice is the reference

`services/book-service` is a complete vertical slice and the template for every service. When in doubt, look there.

- **Packages:** `dev.bookstore.<service>.{config, domain, repository, service, web, web.dto, messaging}`.
- **Entities:** UUID id generated by the application, `@Version` for optimistic locking, no Lombok, getters only
  (add behaviour methods rather than setters), `Instant` for timestamps (`timestamptz` in the database).
- **Schema:** only through Flyway migrations (`V<n>__description.sql`). Hibernate runs with `ddl-auto: validate`.
  Database constraints back up the Bean Validation rules - the database is the last line of defence.
- **Service layer:** it is the transaction boundary. Class-level `@Transactional(readOnly = true)`, write methods
  `@Transactional`. Services return DTOs, entities never leave the layer (`open-in-view` is disabled).
- **DTOs:** Java records. Bean Validation annotations on request DTOs. `Integer` instead of `int` where "missing"
  must differ from `0`.
- **Controllers:** thin; constructor injection only; no business logic.
- **Errors:** every failure is an RFC 9457 `application/problem+json` response, produced by a per-service
  `GlobalExceptionHandler extends ResponseEntityExceptionHandler`. Domain exceptions map to specific statuses,
  the catch-all returns a generic 500 and logs the details server-side, and every problem carries the
  `correlationId`. Type URNs look like `urn:problem-type:<slug>`.
- **Collections** are paged (`Pageable`, bounded page size, `PagedModel` DTO serialisation).
- **Logging:** SLF4J, never log secrets or personal data. The correlation ID comes from `libs/service-common`
  (servlet filter, MDC) and from the gateway; JSON logs (`ecs`) are on in the `docker` and `k8s` profiles.
- **Configuration:** one `application.yml` per service with the profiles `local`, `docker`, `k8s`. Profiles
  differ only in hostnames. No secrets in the repository - placeholders and generated values only.
- **Health:** readiness includes the database but **not** the LLM - the shop must stay up when Ollama is down.
- **Tests (pyramid):** Mockito unit tests for logic, `@WebMvcTest` slice tests for the HTTP contract and the error
  format, and Testcontainers integration tests against the same image as production
  (`pgvector/pgvector:0.8.7-pg18`). Code that can race gets a concurrency test (see `BookApiIntegrationTest`).
  Test the failure paths.
- **Versions:** only in `gradle/libs.versions.toml`. Anything the Spring Boot BOM manages is not pinned again.
- **Containers:** multi-stage Dockerfile, non-root numeric UID 10001, exec-form `ENTRYPOINT`. Kubernetes workloads
  have requests/limits, startup/liveness/readiness probes and a restrictive `securityContext` (see `k8s/base/apps`).

## Commands

```bash
./gradlew build                          # compile + all tests (integration tests need Docker running)
./gradlew :services:book-service:test    # one module
./gradlew :services:book-service:bootTestRun   # run book-service against a throwaway Testcontainers Postgres

docker compose up --build                # whole stack; gateway on http://localhost:8080
docker compose -f docker-compose.yml -f docker-compose.native-ollama.yml up --build   # Ollama on the host

scripts/kind-up.sh                       # kind cluster + build + deploy; gateway on http://localhost:8090
scripts/kind-down.sh                     # delete the cluster
```

Ports: gateway 8080, user 8081, book 8082, order 8083, assistant 8084 (services are only reachable through the
gateway in Compose and Kubernetes). Infrastructure: Postgres 5432, Kafka 9094 (from the host), Ollama 11434.

## Environment notes

- Developed on Windows 11 with Docker Desktop; the scripts are Bash and run in Git Bash (also on macOS / Linux).
- Java 25 comes from the Gradle toolchain (foojay resolver downloads it if missing); the Gradle daemon itself may
  run on an older JDK.
- Spring Boot 4 / Spring Framework 7 / Spring Data 4 / Jackson 3 / Testcontainers 2: package names and starter names
  differ from most tutorials written for Boot 3. Check the real artifact (e.g. the jar contents) before assuming.

## Git

- Conventional Commits (`feat(book): ...`, `fix(gateway): ...`, `docs: ...`), imperative, in English, small and focused.
- Commit messages contain only the description of the change: no `Co-Authored-By` line and no "Generated with ..." trailer.
- Do not commit, push or open pull requests unless asked to.

## Language

Code, comments, commit messages and documentation are English.

## Verification before "done"

Never report work as finished before it is verified:

- `./gradlew build` is green (Docker running, so the integration tests execute - they must not be skipped silently).
- `docker compose up --build` starts healthy and `GET /books` and `GET /assistant/ping` answer through the gateway.
- `scripts/kind-up.sh` ends with all pods `Ready`.

If something could not be verified (for example Ollama models not downloaded), say so explicitly.
